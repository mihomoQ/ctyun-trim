### What's changed

- **Fixed:** the "quarantine destination already exists" error when resuming Apply after a source directory is recreated following a reboot.
- **Improved:** Recreated content is now stored in a separate quarantine location without overwriting or merging existing backups.
- **Improved:** Pending moves remain bound to their recorded destinations, avoiding nested directories on repeated runs.

### 更新内容

- **修复：** 重启后源目录重新生成，导致 Apply 续跑时报“隔离目标已存在”的问题。
- **改进：** 重新生成的内容保存到独立隔离位置，不覆盖或合并原有备份。
- **改进：** 待完成的移动继续使用原记录目标，避免重复运行时出现目录嵌套。
